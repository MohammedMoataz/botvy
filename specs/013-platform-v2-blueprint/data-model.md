# Data Model: Botvy v2

**Feature**: `013-platform-v2-blueprint` | **Date**: 2026-09-05 | **Phase 1 output**

Two server stores, one store per bounded context, one phone mirror.

| Store | Owner contexts | Why |
|---|---|---|
| PostgreSQL 16 (Prisma) | Identity & Access | user decision: accounts and authorisation stay on Postgres; v1 schema and code carry over |
| MongoDB 8 (Mongoose) | Profile, Planning, Reminders, Notifications, Daily Rhythm, Training, Knowledge, Nutrition, Conversations, Meetings & Calendar, Operations | product data |
| SQLite (drift) on the phone | all synced entities | local-first |
| IndexedDB (Dexie) in the extension | tasks, labels, meetings, cursor | offline cache |

Conventions:

- `userId` everywhere is the Postgres `users.id` (uuid) as a string. No cross-store
  joins; Mongo contexts fetch user facts through Identity queries.
- **Syncable documents** (client-minted): `_id` = UUIDv7 string generated by the
  creating client; fields `userId`, `createdAt`, `updatedAt` (set server-side with
  `$currentDate`), `deletedAt` (tombstone), `schemaVersion`. Deleting sets
  `deletedAt` and **never changes `status`**.
- **Server-only documents**: `_id` = ObjectId.
- Uniqueness that involves an optional field uses a **partial index**
  (`{ field: { $exists: true } }`) — MongoDB treats missing/null as one value.
- Times are UTC `Date`s; wall-clock preferences are `"HH:mm"` strings interpreted
  in `profiles.timezone`. Calendar dates are `"YYYY-MM-DD"` in the member's zone.

## 1. PostgreSQL — Identity & Access

```prisma
enum Role       { user  admin }
enum UserStatus { active banned }
enum DeviceKind { android ios chrome_extension web }

model User {
  id            String      @id @default(uuid())
  email         String      @unique            // may be a bare username for the seeded admin
  passwordHash  String?                        // null for Google-only accounts
  googleSub     String?     @unique
  displayName   String?
  role          Role        @default(user)
  status        UserStatus  @default(active)
  createdAt     DateTime    @default(now())
  lastLoginAt   DateTime?
  deletedAt     DateTime?
  refreshTokens RefreshToken[]
  devices       Device[]
}

model RefreshToken {                           // id == jti; rotating; family for reuse detection
  id          String    @id
  userId      String
  familyId    String
  tokenHash   String
  deviceId    String?
  expiresAt   DateTime
  revokedAt   DateTime?
  replacedBy  String?
  createdAt   DateTime  @default(now())
  user        User      @relation(fields: [userId], references: [id], onDelete: Cascade)
  @@index([userId, familyId])
}

model Device {
  id         String     @id @default(uuid())
  userId     String
  installId  String     @unique
  kind       DeviceKind
  name       String?
  fcmToken   String?
  lastSeenAt DateTime?                         // stamped by /sync; drives the sweep's skip rule
  createdAt  DateTime   @default(now())
  user       User       @relation(fields: [userId], references: [id], onDelete: Cascade)
  @@index([userId])
}

model ServiceClient {                          // machine principals (n8n, future services)
  id         String    @id @default(uuid())
  name       String    @unique
  tokenHash  String
  scopes     String[]                          // e.g. ["internal:sweep","internal:tick","internal:alerts"]
  createdAt  DateTime  @default(now())
  lastUsedAt DateTime?
  revokedAt  DateTime?
}

model IdentityOutbox {                         // Identity's events, written in the SAME transaction as the change
  id          String    @id                      // eventId (uuid)
  name        String                             // 'identity.UserRegistered' …
  aggregate   Json                               // { type, id }
  userId      String?
  payload     Json
  occurredAt  DateTime  @default(now())
  forwardedAt DateTime?                          // set by the relay after copying into the Mongo outbox
  @@index([forwardedAt, occurredAt])
}
```

Rules: refresh-token reuse (presenting a revoked/replaced token) revokes the whole
family. Changing the password revokes every family. Banning sets `status=banned`,
revokes all tokens and emits `UserBanned`. Account deletion emits `UserDeleted`;
Mongo contexts delete their documents on it.

## 2. MongoDB collections

### 2.1 Profile context

**`profiles`** — `_id = userId`

```ts
{ _id: string, displayName: string, photoPath: string|null, timezone: string /* IANA */,
  locale: 'en'|'ar', goal: string|null, experience: 'beginner'|'intermediate'|'advanced'|null,
  heightCm: number|null,
  bodyMetrics: [{ at: Date, weightKg?: number, heightCm?: number, note?: string }],  // history, newest last
  symptoms: string[], likedFoods: string[], dislikedFoods: string[], allergies: string[],
  createdAt, updatedAt, schemaVersion: 1 }
```

**`user_preferences`** — `_id = userId`; every value has an operator default in `settings.defaults.*`

```ts
{ _id: string,
  planTomorrowTime: 'HH:mm' /* 21:00 */, endOfDayTime: 'HH:mm' /* 22:00 */,
  morningBriefingTime: 'HH:mm' /* 08:00 */,
  nextPracticeCutoff: 'HH:mm' /* 21:00 */,
  defaultLeadTimes: string[] /* ['1h','0m'] */, mealMode: 'llm'|'library',
  aiSuggestions: boolean, quietHours: { from: 'HH:mm', to: 'HH:mm' }|null,
  weekStartsOn: 1|6|7, checkinEnabled: boolean,
  updatedAt, schemaVersion }
```

Profile photo bytes live on the `media` volume at `/data/media/<userId>/avatar-<hash>.jpg`
and are served by `GET /api/v1/profile/photo` (auth) — no GridFS.

### 2.2 Planning context

**`labels`** (syncable)

```ts
{ _id, userId, name: string, color: string /* #rrggbb, palette default or custom */,
  sortOrder: number, createdAt, updatedAt, deletedAt, schemaVersion }
// index: { userId: 1, updatedAt: 1 }; unique partial { userId: 1, nameLower: 1 } where deletedAt null
```

**`tasks`** (syncable)

```ts
{ _id, userId, title: string, notes: string|null,
  dueAt: Date|null, allDay: boolean,
  priority: 1|2|3|4,                                 // P1 highest
  labelId: string|null, label: { name, color }|null, // Extended Reference snapshot, refreshed on LabelUpdated
  status: 'open'|'completed'|'cancelled', completedAt: Date|null,
  recurrence: { dtstart: Date, rrule: string, mode: 'schedule'|'completion', exdates: Date[] }|null,
  estimatedMinutes: number|null, deferCount: number, deferredFrom: Date|null,
  source: 'app'|'chat'|'extension'|'rhythm',
  createdAt, updatedAt, deletedAt, schemaVersion }
// indexes: { userId, dueAt }, { userId, status, dueAt }, { userId, labelId }, { userId, updatedAt }
```

Status machine: `open → completed | cancelled`; `completed|cancelled → open` (reopen).
Completing a recurring task in mode `schedule` advances `dueAt` to the next
occurrence after the current one; in mode `completion` to `completedAt + interval`.
Delete/restore only toggles `deletedAt`.

### 2.3 Reminders context

**`reminders`** (syncable)

```ts
{ _id, userId, title: string, remindAt: Date, leadTimes: string[] /* '1h','0m','1d' */,
  status: 'active'|'done'|'cancelled', snoozedUntil: Date|null,
  source: 'app'|'chat'|'extension', createdAt, updatedAt, deletedAt, schemaVersion }
// indexes: { userId, remindAt }, { userId, updatedAt }
```

Purge: tombstones older than `settings.reminders.tombstoneDays` are removed by the
sweep; a purge request for a non-tombstone is refused.

### 2.4 Notifications context

**`alerts`** (server-only)

```ts
{ _id: ObjectId, userId,
  source: { kind: 'reminder'|'task'|'meeting'|'rhythm'|'suggestion', id: string, occurrenceAt: Date|null },
  label: string /* '1h' | '0m' | 'prep' | 'evening' | 'morning' | 'suggestion' */,
  notifyAt: Date, title: string, body: string, deepLink: string,
  plannedAt: Date, claimedAt: Date|null, sentAt: Date|null, failedAt: Date|null, error: string|null }
// unique partial { userId, 'source.kind', 'source.id', 'source.occurrenceAt', label }
// index { notifyAt: 1 } partial where sentAt == null
```

Lifecycle: `planned → claimed → sent | failed`. Claim = `findOneAndUpdate({ _id,
claimedAt: null }, { $set: { claimedAt: now } })` so two sweeps cannot both take a
row. Devices whose `lastSeenAt >= plannedAt` are skipped (they hold the local
alarm). Source cancellation (`ReminderCancelled`, `TaskCompleted`, meeting
exdate) deletes unsent alerts for that source. Meeting occurrences get alerts for
a rolling 14-day window.

### 2.5 Daily Rhythm context

**`daily_plans`** — `_id = "<userId>:<YYYY-MM-DD>"`

```ts
{ _id, userId, date: 'YYYY-MM-DD',
  status: 'draft'|'confirmed'|'skipped', autoConfirmed: boolean,   // true when the end-of-day touch set it
  tasks: [{ id, title, priority, dueAt }],            // snapshot at prompt time; re-snapshotted on confirm
  training: { sessionId, title, sport, startAt }|null,
  workoutLine: string|null, mealLine: string|null,     // "Workout: Upper body | Meals: oats, chicken salad, lentil soup"
  promptedAt: Date|null, confirmedAt: Date|null, summarisedAt: Date|null, briefedAt: Date|null,
  createdAt, updatedAt, schemaVersion }
```

**`checkins`** — `_id = "<userId>:<date>"`

```ts
{ _id, userId, date, mood: number|null /* 0..100 */, adhered: boolean|null, note: string|null,
  source: 'chat'|'notification'|'app', createdAt, updatedAt }
```

**`rhythm_states`** — `_id = userId`

```ts
{ _id, lastPlanPromptDate: string|null, lastEndOfDayDate: string|null,
  lastMorningBriefingDate: string|null,
  awaitingCheckin: boolean, awaitingSince: Date|null,
  streak: { current: number, best: number, lastAdheredDate: string|null }, updatedAt }
```

Claim-then-send: the tick sets the touch's claim date (`lastPlanPromptDate`,
`lastEndOfDayDate`, `lastMorningBriefingDate`) **before** building and sending, so a
5-minute tick fires each touch once a day and a gateway that was down at 22:00
catches up when it returns.

### 2.6 Training context

**`athlete_profiles`** — `_id = userId`

```ts
{ _id, sports: ('gym'|'football'|'crossfit'|'calisthenics'|'swimming'|'running'|'cycling'|'other')[],
  slots: [{ id, weekday: 1..7, start: 'HH:mm', durationMin: number, sport: string, location: string|null }],
  updatedAt, schemaVersion }
```

**`sessions`** (syncable) — the scheduled and logged practices; source of truth for "next practice"

```ts
{ _id, userId, plannedAt: Date, durationMin: number, sport: string, title: string, focus: string|null,
  programId: string|null, weekIndex: number|null, slotId: string|null, suggestionId: string|null,
  exercises: [{ id, name, notes: string|null, mediaRefs: [{ type: 'image'|'video', url, caption }],
                sets: [{ targetReps?, targetWeightKg?, targetDurationSec?, targetDistanceM?,
                         actualReps?, actualWeightKg?, actualDurationSec?, actualDistanceM?, done: boolean }] }],
  status: 'planned'|'completed'|'cancelled'|'skipped', completedAt: Date|null, notes: string|null,
  createdAt, updatedAt, deletedAt, schemaVersion }
// indexes: { userId, plannedAt }, { userId, status, plannedAt }, { userId, updatedAt }
```

A saga materialises `planned` sessions from `slots` for the next 14 days (empty
`focus` until a program week or a suggestion fills it). Rest day = no session.
`NextPracticeQuery`: before `nextPracticeCutoff` → today's session (any status);
after → the first `planned` session with `plannedAt > end of today`.

**`programs`** (syncable) — structured plans (library), applied onto sessions

```ts
{ _id, userId, title, sport, source: 'user'|'suggestion'|'link', sourceLinkIds: string[],
  weeks: [{ index, sessions: [{ templateId, weekday: number|null, title, focus,
            exercises: [{ name, sets: [{ targetReps?, targetWeightKg?, ... }], mediaRefs: [] }] }] }],
  status: 'active'|'archived', createdAt, updatedAt, deletedAt, schemaVersion }
```

**`workouts`** (syncable) — the member's own library

```ts
{ _id, userId, name, sport, exercises: [{ name, sets: [...] , notes }], tags: string[],
  createdAt, updatedAt, deletedAt, schemaVersion }
```

### 2.7 Knowledge context

**`links`** (syncable; the phone reads them, writes only add/remove)

```ts
{ _id, userId, url: string, normalizedUrl: string,
  kind: 'article'|'website'|'video'|'playlist', parentLinkId: string|null,   // playlist children
  title: string|null, tags: string[] /* sports */,
  status: 'queued'|'fetching'|'extracting'|'summarising'|'done'|'failed',
  failReason: string|null, attempts: number, docId: ObjectId|null,
  addedAt: Date, processedAt: Date|null, createdAt, updatedAt, deletedAt, schemaVersion }
// unique partial { userId, normalizedUrl } where deletedAt null; index { status, updatedAt }
```

State machine: `queued → fetching → extracting → summarising → done`; any step
→ `failed{reason}`; `failed → queued` on retry (attempts+1, capped by
`settings.knowledge.maxAttempts`).

**`knowledge_docs`** (server-only)

```ts
{ _id: ObjectId, linkId, userId, sourceUrl, title, author: string|null, publishedAt: Date|null,
  text: string /* extracted, capped at settings.knowledge.maxChars */, transcript: string|null,
  summary: string, keyPoints: string[], media: [{ type: 'image'|'video', url, caption }],
  durationSec: number|null, model: string, tokens: number, createdAt }
```

**`suggestions`** (server-only; read by clients over GraphQL)

```ts
{ _id: ObjectId, userId, kind: 'session', forDate: 'YYYY-MM-DD', sport, sessionId: string|null,
  draft: { title, focus, exercises: [...] }, sourceLinkIds: string[], rationale: string,
  status: 'pending'|'accepted'|'dismissed', acceptedSessionId: string|null, createdAt, updatedAt }
```

### 2.8 Nutrition context

**`meals`** (syncable)

```ts
{ _id, userId, name, kind: 'breakfast'|'lunch'|'dinner'|'snack'|'any', ingredients: string[],
  tags: string[], createdAt, updatedAt, deletedAt, schemaVersion }
```

**`meal_suggestions`** — `_id = "<userId>:<date>"`

```ts
{ _id, userId, date, mode: 'llm'|'library', meals: [{ kind, name }], line: string|null,
  withheld: boolean, withheldReason: string|null, model: string|null, createdAt }
```

### 2.9 Conversations context

**`conversations`** (syncable, client-minted `_id`)

```ts
{ _id, userId, kind: 'coach'|'planner'|'free', title: string, pinned: boolean, archived: boolean,
  clearedUpToSeq: number, lastMessageAt: Date|null, createdAt, updatedAt, deletedAt, schemaVersion }
// unique partial { userId, kind } where kind in ['coach','planner']; index { userId, updatedAt }
```

**`messages`** (immutable; server-only `_id`)

```ts
{ _id: ObjectId, userId, conversationId, seq: number /* per-user monotonic */,
  role: 'user'|'assistant'|'system', content: string, clientId: string|null, composedAt: Date|null,
  intent: { name, args }|null, usage: { model, promptTokens, completionTokens }|null, createdAt }
// unique { userId, seq }; unique partial { userId, clientId }; index { conversationId, seq }
```

**`counters`** — `_id = "<userId>:messages"`, `{ value: number }`; `findOneAndUpdate
$inc` issues `seq`. The phone pulls `seq > lastSeq`. Because messages are
immutable, a column added later can never reach a device that already holds the
row — mark the cache and re-pull, never edit in place.

**`quick_questions`** (config + user-added)

```ts
{ _id, scope: 'coach'|'planner'|'free', text: { en: string, ar: string }, mood: 'any'|'low'|'ok',
  order: number, userId: string|null /* null = global */, enabled: boolean }
```

### 2.10 Meetings & Calendar context

**`meetings`** (syncable)

```ts
{ _id, userId, title, description: string|null,
  startAt: Date, durationMin: number, allDay: boolean, lockTimezone: string|null,
  location: { onlineLink: string|null, address: string|null },
  prepNotes: string|null, prepMinutes: number,
  reminderOffsets: number[] /* minutes before, e.g. [1440, 30] */,
  recurrence: { dtstart: Date, rrule: string /* RFC 5545 */, exdates: Date[],
                overrides: [{ originalStart: Date, startAt?: Date, durationMin?: number, title?: string,
                              location?: {...}, cancelled?: boolean }] }|null,
  status: 'scheduled'|'completed'|'cancelled', createdAt, updatedAt, deletedAt, schemaVersion }
// indexes: { userId, startAt }, { userId, updatedAt }
```

Occurrences are computed with `rrule` for the requested window; `exdates` remove,
`overrides` replace. Never stored as rows.

**`calendar_events`** (syncable) — non-meeting events

```ts
{ _id, userId, title, notes: string|null, startAt, endAt, allDay, color: string|null,
  recurrence: {...}|null, createdAt, updatedAt, deletedAt, schemaVersion }
```

### 2.11 Shared infrastructure collections

**`outbox`** (server-only)

```ts
{ _id: ObjectId, eventId: string /* uuid */, name: string /* 'planning.TaskCompleted' */,
  context: string, aggregate: { type, id }, userId: string|null, payload: object,
  occurredAt: Date, deliveredAt: Date|null, attempts: number, lastError: string|null }
// index { deliveredAt: 1, occurredAt: 1 }; TTL on deliveredAt (7 d)
```

Identity's events do not start here: they are written to PostgreSQL's
`identity_outbox` in the same transaction as the change (§1) and copied into this
collection by the relay, keyed by the same `eventId`, so a duplicate copy is a
no-op.

**`settings`** — `_id = key`, `{ value: any, updatedAt, updatedBy }`; keys and zod
schemas live in `settings.registry.ts`. Registry (initial):

| Key | Default | Read by |
|---|---|---|
| `defaults.timezone` | `Africa/Cairo` | new profiles |
| `defaults.planTomorrowTime` / `endOfDayTime` / `morningBriefingTime` / `nextPracticeCutoff` | `21:00` / `22:00` / `08:00` / `21:00` | new preferences |
| `defaults.leadTimes` | `["1h","0m"]` | new preferences, reminders |
| `defaults.mealMode` / `aiSuggestions` | `llm` / `true` | new preferences |
| `reminders.tombstoneDays` | `30` | sweep **and** sync full-snapshot rule |
| `notifications.sweepBatch` / `expiryHours` | `200` / `24` | sweep |
| `rhythm.checkinWindowHours` | `12` | check-in capture |
| `chat.historyLimit` | `20` | prompt assembly |
| `llm.chatModel` / `extractModel` / `summarizeModel` / `numCtx` | `qwen2.5:3b-instruct` ×3 / `8192` | LLM client |
| `knowledge.maxAttempts` / `maxChars` / `playlistMaxItems` | `3` / `60000` / `50` | ingestion |
| `push.copy` | per kind, per language | alerts |
| `automation.subscriptions` | `[]` | outbox relay → n8n webhooks |
| `labels.palette` | 12 hex colours | label picker |

**`ops_heartbeats`** — `_id = job` (`notifications.sweep`, `rhythm.tick`,
`outbox.relay`, `knowledge.ingest`), `{ lastRunAt, lastOkAt, lastDurationMs,
lastError }`; stale after 15 min → `/health` degraded.

**`usage_log`** — `{ _id, userId, kind: 'chat'|'intent'|'summarize'|'suggest'|'plan', model,
promptTokens, completionTokens, ms, createdAt }`; TTL 90 d.

**`audit_log`** — `{ _id, actor: Principal, action, target: { type, id }, at, meta }`
for admin actions (role change, ban, setting patch, workflow run).

## 3. Phone mirror (drift / SQLite)

New database file `botvy_v2.sqlite` (v1 data is not migrated). Every synced table
mixes in:

```dart
mixin SyncColumns on Table {
  TextColumn get id => text()();                 // uuidv7, minted here
  DateTimeColumn get updatedAt => dateTime()();  // when THIS device last edited
  DateTimeColumn get baseUpdatedAt => dateTime().nullable()(); // server's value for the version last pulled; never touched by a local edit
  TextColumn get pendingOp => text().nullable()(); // create|update|delete|restore|purge
  IntColumn get pushAttempts => integer().withDefault(const Constant(0))();
  DateTimeColumn get deletedAt => dateTime().nullable()();
}
```

Tables: `tasks`, `labels`, `reminders`, `meetings`, `calendar_events`, `sessions`,
`programs`, `workouts`, `meals`, `links`, `conversations`, `messages` (pull-only,
by `seq`; `syncState` for outbox), `daily_plans`, `checkins`, `profile`,
`preferences`, `athlete_profile`, `alerts_local` (planned pings derived from
rows), `key_values` (cursor, lastSeq, install id).

Rules carried from v1 (each has a test):

- Filters meaning "not this pending op" are written
  `pendingOp.isNull() | pendingOp.equals(x).not()`.
- `schemaVersion` bump ⇔ matching `MigrationStrategy` branch; `addColumn` on a
  table created in an earlier branch is guarded `if (from >= N && from < M)`.
- The delete sweep runs only when the server answered `full: true`.
- Rejections branch on `entity` before touching any table.
- A row with `baseUpdatedAt == null` was never seen by the server: delete/purge
  locally without a round trip.

## 4. Extension cache (Dexie)

`tasks`, `labels`, `meetings`, `pending_ops`, `meta` (cursor, tokens live in
`chrome.storage.local`). Same push/pull protocol as the phone, subset of entities.

## 5. Sync coverage

| Entity | Push from clients | Pull | Delete sweep on full |
|---|---|---|---|
| tasks, labels, reminders, meetings, calendar_events, sessions, programs, workouts, meals, conversations | yes | yes | yes |
| links | add / remove only | yes | yes |
| messages | via chat (WS or batch) | by `seq` | no (immutable) |
| profile, preferences, athlete_profile | yes (field allowlist, no conflict check — client and server write disjoint fields) | yes | n/a |
| daily_plans, checkins | confirm / record only | yes | n/a |
| suggestions, knowledge_docs | no | GraphQL only | n/a |

## 6. State machines (summary)

| Entity | States | Transitions |
|---|---|---|
| Task | open, completed, cancelled (+ deleted flag) | open→completed/cancelled; completed/cancelled→open; delete/restore orthogonal |
| Reminder | active, done, cancelled (+ snoozedUntil, deleted) | active→done/cancelled; snooze keeps active; restore returns as-was; reactivate = new time |
| Alert | planned, claimed, sent, failed | claim is atomic; cancel deletes unsent |
| Daily plan | draft, confirmed, skipped | prompt→draft; confirm; skip |
| Session | planned, completed, cancelled, skipped | log sets while planned; complete; cancel/skip |
| Link | queued, fetching, extracting, summarising, done, failed | linear; failed→queued on retry |
| Suggestion | pending, accepted, dismissed | accept creates/updates a session |
| Meeting | scheduled, completed, cancelled | per-occurrence overrides/exdates do not change series status |
| Refresh token family | active, revoked | reuse → family revoked |
