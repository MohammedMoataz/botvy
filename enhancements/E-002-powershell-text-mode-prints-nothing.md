# E-002 — `check-prerequisites.ps1` text mode prints nothing

**Area**: tooling · **Status**: open · **Found**: P2, while adding the bash halves

## What

In `.specify/scripts/powershell/check-prerequisites.ps1` and `setup-tasks.ps1`,
the available-documents list is produced by piping a function that writes its
own output:

```powershell
Test-FileExists -Path ... -Description '...' | Out-Null
```

`Out-Null` discards the function's `Write-Output`, so the script prints the
`AVAILABLE_DOCS:` header and then nothing at all. The bash halves print the four
`[OK] research.md`-style lines the header promises.

## Why it is not a defect worth a hotfix

`--json` is unaffected, and `--json` is the only mode the seven `speckit-*`
skills actually parse. Both halves are byte-identical there — measured, not
assumed. Nothing automated reads the broken output.

It is also somebody else's file: these scripts are generated by spec-kit and
hash-tracked in `.specify/integrations/claude.manifest.json`, so editing them is
deliberate drift that a future `specify` run may undo.

## What it costs

A person who runs the script by hand to see what a feature is missing gets an
empty list and reasonably concludes nothing is missing.

## What fixing it takes

Drop the `| Out-Null` and let the function's output through, or capture it and
print it. One line in each of two files. The decision to make first is whether
this repository is willing to hold local edits to spec-kit's generated scripts —
see E-003, which has the same question at its centre.
